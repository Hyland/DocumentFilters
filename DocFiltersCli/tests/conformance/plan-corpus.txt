# ---------------------------------------------------------------------------
#  docfilters CLI — plan conformance corpus
#
#  Shared by the C#, Python, Java and C++17 implementations. Each runs the
#  arguments through stages 1 to 3 — parse, bind, plan — with the input walk
#  feeding the planner, and compares the canonical plan text. No document is
#  opened, so no license and no native library are needed.
#
#  Every case here encodes a decision from the CLI design that the four
#  implementations could otherwise diverge on.
#
# ---------------------------------------------------------------------------
#  WHAT A CASE IS GIVEN
#
#  A case names the command line after $, then the filesystem it runs against
#  after <, then what the run must produce after =. The suite loads the < lines
#  into an in-memory IFileSystem before the command line runs:
#
#    < tree    <path> <path> …     files, parents created implicitly;
#                                  a trailing / makes an empty directory
#    < link    <path> <target>     a directory symlink, for -L/--follow
#    < hidden  <path>              marks an existing entry hidden
#
#  Tests never touch the real filesystem, and that is load-bearing rather than
#  hygiene. A real directory listing has no defined order and differs between
#  ext4, NTFS and APFS, so a corpus backed by real files could not be
#  byte-identical across four languages and three platforms. The fake also
#  models symlinks and hidden entries as plain sets, which is what lets
#  --follow and --include-hidden be contract at all: creating a symlink on
#  Windows needs a privilege most checkouts do not have, and "hidden" is a
#  dot-prefix on POSIX and a file attribute on Windows.
#
#  The fake's own semantics are therefore part of this contract, specified by
#  InMemoryFileSystemTests. Every port translates those alongside these cases;
#  they are a prerequisite, not optional scaffolding.
#
#  A case that walks several files passes --sort. Directory order without it is
#  unspecified by design — that is what --sort exists to fix — and a contract
#  cannot assert an order that is undefined.
#
#  A case whose error is raised before the walk needs no tree: an unknown
#  format, a bad value, a missing value and every validator rule fail without
#  one. E_NO_INPUTS, E_OUTFILE_MULTI_INPUT, E_OUTPUT_COLLISION and
#  E_OUTPUT_EXISTS are raised by the planner, after the walk, so those cases
#  declare a tree.
#
# ---------------------------------------------------------------------------
#  THE EMISSION RULE
#
#  The plan is compared as a whole document, in order, so which lines appear
#  has to be a property of the command rather than of the arguments:
#
#      A command emits its full line set, always, in the fixed order below,
#      with defaults written out explicitly. A line is never omitted because
#      its value happens to be the default.
#
#  Order and line set per command:
#
#    convert   command to inputs walk match types subfiles on-error pages
#              cardinality target*|pattern* exit
#    extract   command inputs walk match types subfiles on-error include
#              exclude images make-dirs sub-id cardinality exit
#    list      command inputs walk match types subfiles on-error json
#              cardinality exit
#    identify  command inputs walk match types on-error json capabilities exit
#    meta      command inputs walk match types on-error json cardinality exit
#    formats   command json filter exit
#    options   command json filter applies-to exit
#
#  walk, match, types, subfiles and on-error are always contiguous and in that
#  order, for every command that has them: they are exactly the fields
#  SharedOptions.ToCanonicalString renders as one block, so a command's own
#  fields (convert's pages; extract's include/exclude/images/make-dirs/sub-id)
#  always come after that whole block rather than inside it. This is a
#  correction from an earlier draft, which put pages and extract's own fields
#  before on-error and so split the shared block in two for those commands.
#
#  A command emits a line only for a concept it has. identify declares no
#  output group, so it has no cardinality; formats and options read no inputs,
#  so they have neither. meta and identify have no subfile group.
#
#  = inputs lists what the walk selected, in processing order — not the paths
#  as typed. A case naming a directory states the files that come out of it, so
#  --max-depth, --glob, --regex, --follow and --include-hidden are asserted
#  here rather than only in one language's own suite.
#
#  Default renderings:
#
#    = walk          depth=unlimited follow=no sort=no hidden=no
#    = match         none
#    = types         include=none exclude=none
#    = subfiles      disabled
#    = pages         all
#    = on-error      skip
#
#  target and pattern are emitted only by convert, one per input in input
#  order: target for a resolved path, pattern for a per-page format whose
#  filenames depend on the document's page count. extract, list and meta
#  produce names that only exist once a document is open — subfile names come
#  from the container — so they state their cardinality and stop there.
#
# ---------------------------------------------------------------------------
#  CASE FOLDING
#
#  An argument whose valid values this tool enumerates matches them after an
#  ASCII-only case fold, and renders the folded value in the plan:
#
#      --to  --on-error  --applies-to
#      --log-level  --debug-log-level
#
#  Everything else is used exactly as typed: paths, globs, regular expressions,
#  --out-name templates, --filter text, passwords, --codepage, and the --options
#  string, all of which either name something outside this tool or are matched
#  by something outside it.
#
#  ASCII-only is the load-bearing half. A locale-aware fold turns TIFF into
#  'tiff' with a dotless i under a Turkish locale, in C#, Java and Python
#  alike, so the fold maps A-Z to a-z and touches nothing else. std::tolower is
#  itself locale-sensitive.
#
# ---------------------------------------------------------------------------
#  ERROR MESSAGES
#
#  stderr is contract, so every failing case states its message. Two shapes
#  carry every usage error, both plain concatenation so that four languages
#  produce the same bytes:
#
#      <argument> and <argument> cannot be used together
#      <argument> does not accept the value '<value>'
#
#  An argument is always named by its long form, whichever form was typed, and
#  a contradictory pair is always named in argument-table order — never in argv
#  order, which D8 established is not portable.
#
#  E_INIT_FAILED, E_LIMIT_EXCEEDED and E_DOCUMENT_FAILED need a live engine —
#  the library must fail to initialise, a document must fail to open, or one
#  must outrun --timeout — so no case here can provoke them. They are named in
#  ErrorCodeTests instead, and exercised by the CLI tests and the end-to-end
#  script. Every other code is exercised here.
# ---------------------------------------------------------------------------

# === output cardinality ====================================================

# --out-dir gives each input its own output.

$ convert --to pdf --out-dir out a.docx b.docx
< tree          a.docx b.docx
= command       convert
= to            pdf canvas single-file hidef
= inputs        a.docx, b.docx
= walk          depth=unlimited follow=no sort=no hidden=no
= match         none
= types         include=none exclude=none
= subfiles      disabled
= on-error      skip
= pages         all
= cardinality   per-input
= target        out/a.pdf
= target        out/b.pdf
= exit          0

# The hard error the design document is explicit about: never a guess. Raised
# by the planner, so the inputs have to exist for it to be reached at all.

$ convert --to pdf --out-file one.pdf a.docx b.docx
< tree          a.docx b.docx
= error         E_OUTFILE_MULTI_INPUT
= message       --out-file takes a single input; use --combine to merge several into one document
= exit          4

# The same command line with a per-page format reports the format problem, not
# the input count. Two rules match here and the stage each runs in decides
# which is reported: the validator runs before the walk, and it can see that
# 'png' cannot go to a single --out-file without knowing how many inputs there
# are. That is also the more useful of the two, because removing an input would
# not fix it.

$ convert --to png --out-file one.png a.docx b.docx
< tree          a.docx b.docx
= error         E_OUTFILE_NEEDS_SINGLE_FILE
= message       --out-file can only name a format that writes one file; 'png' writes one per page
= exit          2

# === attached values =======================================================
#
#  A switch takes no value. Accepting an attached one enabled the flag and left
#  the value behind as a positional, so --overwrite=false turned overwriting ON
#  and added 'false' to the input list -- the opposite of what was typed, and
#  reported as a missing file rather than as bad usage.

$ convert --to text --out-dir out --overwrite=false a.docx
= error         E_BAD_VALUE
= message       --overwrite takes no value
= exit          2

$ convert --to text --out-dir out --combine=yes a.docx
= error         E_BAD_VALUE
= message       --combine takes no value
= exit          2

# === help topics ===========================================================
#
#  'help' and 'version' are verbs but not commands: they process no documents and
#  accept no shared options, so they have no argument surface to print. Asking
#  for one used to reach the describer anyway and terminate the process -- an
#  unhandled ArgumentException in C#, an uncaught std::invalid_argument in C++.
#  Rejecting at binding is what makes it an ordinary usage error in both.

$ help help
= error         E_BAD_VALUE
= message       'help' has no arguments of its own; run 'docfilters help' to list the commands
= exit          2

$ help version
= error         E_BAD_VALUE
= message       'version' has no arguments of its own; run 'docfilters help' to list the commands
= exit          2

= error         E_OUTPUT_IS_INPUT

# Two inputs whose outputs would land on the same path.

$ convert --to text --out-dir out a/report.docx b/report.docx
< tree          a/report.docx b/report.docx
= error         E_OUTPUT_COLLISION
= message       two inputs would write to the same output; use --out-name to distinguish them
= exit          4

# The same pair differing only in case, on a filesystem that tells names apart
# that way: two files, two outputs, no collision. Whether these collide is a
# property of the target filesystem, not of the host or of a fixed rule, and the
# corpus filesystem is case-sensitive -- so this case reads the same on every
# platform. The other answer, where the filesystem folds case and these are one
# file, is asserted by each language's own OutputPlanner tests, which can say
# what their filesystem does.

$ convert --to text --sort --out-dir out a/Report.docx b/report.docx
< tree          a/Report.docx b/report.docx
= command       convert
= to            text text single-file
= inputs        a/Report.docx, b/report.docx
= walk          depth=unlimited follow=no sort=yes hidden=no
= match         none
= types         include=none exclude=none
= subfiles      disabled
= on-error      skip
= pages         all
= cardinality   per-input
= target        out/Report.txt
= target        out/report.txt
= exit          0

# A malformed template fails when the argument is read, not when the first name
# is rendered. out-names.txt covers the template language itself; this covers
# the wiring, which that file cannot see: a port could parse templates
# perfectly and still never call the parser from --out-name.

$ convert --to text --out-dir out --out-name {unknown} a.docx
= error         E_BAD_TEMPLATE
= message       --out-name does not accept the value '{unknown}'
= exit          2

# Escaping the output directory is rejected the same way, and for the same
# reason: it comes from the template's own literal text, so no rendered result
# would reveal it.

$ convert --to text --out-dir out --out-name ../{stem}.{ext} a.docx
= error         E_BAD_TEMPLATE
= message       --out-name does not accept the value '../{stem}.{ext}'
= exit          2

# A per-page format needs {page} in the template, or every page of a document
# resolves to the same filename.

$ convert --to png --out-dir out --out-name {stem}.{ext} a.docx
= error         E_TEMPLATE_NEEDS_PAGE
= message       --out-name must contain {page} when the format writes one file per page
= exit          2

# A structure report needs a canvas format. One document open cannot serve both
# a report and a text conversion: page structures only exist on a paginated
# handle, text extraction only works on a text one, so either half fails
# whichever format bit is chosen. Refused before anything opens.
#
# The named report is the first requested in argument-table order, so that the
# same pair of flags produces the same message however they were typed.

$ convert --to text --out-dir out --bookmarks a.docx
= error         E_REPORT_NEEDS_HIDEF
= message       --bookmarks needs a high-definition format; 'text' is text-mode only
= exit          2

$ convert --to md-text --out-dir out --bookmarks --fonts a.docx
= error         E_REPORT_NEEDS_HIDEF
= message       --fonts needs a high-definition format; 'md-text' is text-mode only
= exit          2

# docpack is refused too, and for its own reason: it opens with no format bit at
# all, so it has no pages to report on either.

$ convert --to docpack --out-dir out --dimensions a.docx
= error         E_REPORT_NEEDS_HIDEF
= message       --dimensions needs a high-definition format; 'docpack' writes a document pack, not pages

# === fingerprint ============================================================
#
# --fingerprint renders a page only to read a fingerprint attribute off it —
# confirmed against doc2text's own --fingerprint (main.cpp), which forces a
# throwaway image render and discards it through a temporary stream rather than
# the requested target. The render is never kept here either, so every argument
# whose entire purpose is to name or expose that output is a contradiction
# instead of a silent no-op. --redact, --form and --watermark are unaffected:
# they decorate the same throwaway render, so there is nothing for them to
# contradict.

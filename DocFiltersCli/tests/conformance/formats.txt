# ---------------------------------------------------------------------------
#  docfilters CLI — the --to format catalogue
#
#  Shared by the C#, Python, Java and C++17 implementations. This table is the
#  specification for FormatCatalog: every implementation must resolve exactly
#  these tokens, to exactly these properties.
#
#    kind         text | canvas | docpack
#                   text    — streamed from the extractor, no canvas
#                   canvas  — rendered page by page onto an output canvas
#                   docpack — Extractor.MakeDocPack, neither of the above
#    single-file  yes = one artifact however many pages
#                 no  = one file per page, which makes --out-file and --stdout
#                       illegal and forces {page} into the default template
#    combine      whether several inputs may merge into one output (--combine).
#                 A separate question from single-file: docpack writes one file
#                 per document but cannot hold two documents, because
#                 Extractor.MakeDocPack takes one extractor
#    hidef        whether the format can carry high-definition paginated
#                 output. A property of the format, not of any one document:
#                 it describes what the target can hold, which is why it
#                 appears in a plan's "to" line
#    ext          filename extension, no leading dot, used by {ext}
#    options      canvas options the format itself contributes, appended after
#                 whatever --canvas-options supplies; 'none' for most.
#                 The order is behaviour, not formatting: the engine resolves a
#                 repeated key to its FIRST occurrence, so putting the user's
#                 options in front is what lets them override any of these. A
#                 port that prepends instead will silently ignore
#                 --canvas-options for every key named here.
#
#  Several entries are not a straight mapping onto one engine enum value, which
#  is the whole reason this table exists:
#    md vs md-text     high-definition markdown vs text-mode markdown
#    html vs html5     flow HTML vs paginated high-definition HTML
#    json vs mdast     the same canvas under two schemas
#    docpack           a third rendering path entirely
#    web-safe          the only format whose extension the engine chooses
#
#  Tokens are matched after an ASCII-only case fold, so PDF, Pdf and pdf all
#  resolve to the same entry. ASCII-only matters: a locale-aware fold turns TIFF
#  into 'tiff' with a dotless i under a Turkish locale in C#, Java and Python
#  alike, and std::tolower is locale-sensitive too. Fold A-Z to a-z and touch
#  nothing else.
# ---------------------------------------------------------------------------

# === canvas, single file ===================================================

$ md
= kind          canvas
= single-file   yes
= combine       yes
= hidef         yes
= ext           md
= options       none

# html5 and svg both rasterise each page into a sibling image file and lay a
# transparent text layer over it. This tool writes only the markup, so without
# the inlining option every page renders blank — the text is there, at alpha 0,
# over a background image that was never written. Turning it on embeds the
# raster as a data: URI and the output is one self-contained file. doc2text
# forces the same two options for the same reason (main.cpp).

$ html5
= kind          canvas
= single-file   yes
= combine       yes
= hidef         yes
= ext           html
= options       HTML_INLINE_IMAGES=ON;

$ json
= kind          canvas
= single-file   yes
= combine       yes
= hidef         yes
= ext           json
= options       none

# The one format whose extension the engine picks: png, gif, jpg or webp
# depending on the bit depth it settles on, which is not knowable until the page
# has been rendered. So the plan names the file '.unknown' and execution renames
# it once the real type is detected. The renamed path goes through the same
# per-page existence check as any other per-page output, so --overwrite still
# protects an existing file.

$ web-safe
= kind          canvas
= single-file   no
= combine       no
= hidef         yes
= ext           unknown
= options       none

# === the third path ========================================================

# Extractor.MakeDocPack takes one extractor, so a pack holds one document. That
# is why 'combine' is its own property: docpack writes a single file, like pdf,
# but cannot merge several inputs into it.

$ docpack
= kind          docpack
= single-file   yes
= combine       no
= hidef         yes
= ext           docpack
= options       none
